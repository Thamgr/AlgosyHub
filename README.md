# AlgosyHub

Учебная платформа для групп по спортивному программированию.

## Быстрый старт

```bash
cp .env.example .env
# заполнить .env
docker compose up --build
```

Backend: http://localhost:8000  
Frontend: http://localhost:5173  
API docs: http://localhost:8000/docs

## Разработка

```bash
# Backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload

# Frontend
cd frontend
npm install
npm run dev
```

## Миграции

```bash
cd backend
alembic upgrade head
alembic revision --autogenerate -m "description"
```

## Timus

В создании и настройках контеста выберите источник **Timus** и укажите номер
задачи, например `1000`, или ссылку на её условие. Поддерживается основной архив
Timus (`space=1`): импорт названия, меток и сложности, просмотр условия,
AI-подсказки и переход к форме отправки решения.

В настройках профиля привяжите числовой ID автора из публичной ссылки
`https://acm.timus.ru/author.aspx?id=12345`. Это не секретный `JUDGE_ID`
с буквенным суффиксом. Пароль и ключ API для опроса Timus не нужны.
Посылки читаются с публичной страницы статуса; время Timus переводится из
часового пояса Екатеринбурга в UTC. Как и у остальных адаптеров, за один опрос
синхронизируются последние 50 посылок пользователя.

Для существующей базы требуется миграция `0005` (`alembic upgrade head`).
При запуске через Docker Compose миграции применяются автоматически.

## Время окончания контеста

При создании, включая автоподбор, необходимо указать дату и время окончания.
Форма использует часовой пояс браузера, API принимает `ends_at` в ISO 8601
с часовым поясом, например `2026-09-25T18:00:00+03:00`. Владелец контеста
может изменить срок в настройках, в том числе после его истечения.

В зачёт идут только посылки с временем отправки **строго раньше** `ends_at`.
Посылка, отправленная вовремя, учитывается и при позднем получении её вердикта.
Поздние посылки сохраняются в общей истории, но не входят в положение и список
посылок контеста. Изменение срока сразу пересчитывает зачёт по сохранённой
истории: сокращение исключает поздние посылки, продление возвращает их.
После истечения срока запущенный контест отображается завершённым;
продление такого контеста снова открывает зачёт. Кнопка «Завершить» также
устанавливает время отсечения, не сдвигая уже прошедший срок вперёд.
Старые контесты без `ends_at` сохраняют прежнее поведение до установки срока.

## Тесты

```bash
cd backend
pip install -r requirements-dev.txt
PYTHONPATH=. pytest -q
```

По умолчанию тесты используют изолированную SQLite в памяти. Для проверки
на PostgreSQL задайте `TEST_DATABASE_URL`, указывающий на отдельную тестовую
базу: тесты создают и удаляют таблицы в ней.
