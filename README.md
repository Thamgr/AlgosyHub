# AlgosyHub

Учебная платформа для групп по спортивному программированию.

## Быстрый старт

```bash
cp .env.example .env
# заполнить .env
docker compose up --build
```

Backend: http://localhost:8000  
Frontend: http://localhost:5173  
API docs: http://localhost:8000/docs

## Production: algosy.thamgr.space

Платформа развёрнута на `5.178.109.118` в `/opt/algosyhub`.
Используется отдельный `compose.production.yml`: снаружи доступны только
HTTP/HTTPS, Caddy автоматически выпускает и продлевает TLS-сертификат.
Контейнеры запускаются после перезагрузки сервера; PostgreSQL и сертификаты
хранятся в постоянных Docker volumes. Логи ограничены по размеру.

В серверном `.env` нужны настройки интеграций из `.env.example`, уникальный
`SECRET_KEY` и случайный `DB_PASSWORD` (hex, минимум 32 байта).
Файл должен иметь права `600`; секреты не добавляются в Git.
Не меняйте `DB_PASSWORD` без соответствующей смены пароля в PostgreSQL.

Команды на сервере:

```bash
cd /opt/algosyhub
docker compose -f compose.production.yml up -d --build --wait
docker compose -f compose.production.yml ps
docker compose -f compose.production.yml logs --tail=100 backend caddy
curl --fail https://algosy.thamgr.space/healthz
```

Перед обновлением исходников и миграциями сохраните резервную копию базы:

```bash
cd /opt/algosyhub
install -d -m 700 backups
umask 077
docker compose -f compose.production.yml exec -T db \
  pg_dump -U postgres -d algosyhub -Fc > "backups/algosyhub-$(date +%Y%m%d-%H%M%S).dump"
```

Обновляйте исходники, сохраняя серверный `.env`, затем повторяйте `up`.
Миграции применяются автоматически перед запуском API.
Не используйте `down -v`: эта команда удаляет постоянные данные.

## Глобальные настройки

Администратор открывает «Настройки платформы» в шапке (`/platform-settings`).
Переключатели сохраняются автоматически в базе и по умолчанию включены:

- **Регистрация пользователей**: скрывает ссылку и форму регистрации,
  а также запрещает создание аккаунтов через API. Вход продолжает работать.
- **AI-подсказки**: скрывает блок подсказок и настройки подсказок в контестах,
  запрещает чтение кэша, генерацию и перегенерацию. Индивидуальные настройки
  контестов сохраняются и снова действуют после включения глобального флага.

Открытые страницы обновляют настройки при переходах, возврате в окно и каждые
30 секунд. API проверяет актуальные значения при каждом запросе.

Право администратора независимо от роли учителя и не выдаётся при регистрации.
Его можно назначить только существующему аккаунту командой на сервере:

```bash
cd /opt/algosyhub
docker compose -f compose.production.yml exec -T backend python -m app.manage admin USERNAME
# Отозвать: добавить --revoke. Для обновления интерфейса перезагрузите страницу.
```

Миграция `0006` добавляет настройки и право администратора без изменения
существующих аккаунтов. `GET /api/v1/platform-settings` публично возвращает
только два флага, `PATCH` доступен только администратору.

## Личный кабинет

На своей странице `/u/USERNAME` настройки расположены справа от профиля и
статистики; на узком экране — ниже. В одном блоке находятся поле «Фамилия Имя»
и ники/ID проверяющих систем. ФИ необязательны, отображаются в
профиле и могут быть очищены. Ник после регистрации не меняется.
Старый адрес `/settings` перенаправляет к настройкам в профиле.

`PATCH /api/v1/me` принимает только `full_name` (до 201 символа). Значение
хранится целиком, пробелы по краям удаляются. Изменение ника и прав через этот
API запрещено. Миграция `0009` объединяет ранее сохранённые фамилию и имя,
сохраняя логины и привязки аккаунтов.

## Timus

В создании и настройках контеста выберите источник **Timus** и укажите номер
задачи, например `1000`, или ссылку на её условие. Поддерживается основной архив
Timus (`space=1`): импорт названия, меток и сложности, просмотр условия,
AI-подсказки и переход к форме отправки решения.

В настройках профиля привяжите числовой ID автора из публичной ссылки
`https://acm.timus.ru/author.aspx?id=12345`. Это числовая часть `JUDGE_ID`
без букв в конце: например, из `12345AB` нужно ввести `12345`.
Полный `JUDGE_ID`, пароль и ключ API для опроса Timus не нужны.
Посылки читаются с публичной страницы статуса; время Timus переводится из
часового пояса Екатеринбурга в UTC. Как и у остальных адаптеров, за один опрос
синхронизируются последние 50 посылок пользователя.

Для существующей базы требуется миграция `0005` (`alembic upgrade head`).
При запуске через Docker Compose миграции применяются автоматически.

## Время и видимость контеста

Необязательное поле `starts_at` задаёт автоматический запуск. До указанного
времени контест остаётся черновиком; после начала запущен, после окончания
завершён. Статус вычисляется на сервере, независимо от открытого браузера.
Очистка поля в настройках убирает расписание. Без него используется кнопка
«Запустить». Ранний запуск кнопкой переносит запланированное начало на текущий момент.
Посылки с временем отправки **раньше** `starts_at` не идут в зачёт;
посылка ровно в момент начала учитывается. Изменение начала пересчитывает
зачёт по сохранённым посылкам так же, как изменение окончания.

Флаг «Виден участникам» (`is_visible`) доступен при создании, автоподборе и
редактировании. Если он выключен, только владелец видит контест в списках и
может открыть его, задачи, положение и посылки через API. Если включён,
действуют ограничения выбранных групп. Флаг не меняет расписание и историю
результатов. У существующих контестов после миграции он включён.

При создании, включая автоподбор, необходимо указать дату и время окончания.
Форма использует часовой пояс браузера, API принимает `ends_at` в ISO 8601
с часовым поясом, например `2026-09-25T18:00:00+03:00`. Владелец контеста
может изменить срок в настройках, в том числе после его истечения.

В зачёт идут только посылки с временем отправки **строго раньше** `ends_at`.
Посылка, отправленная вовремя, учитывается и при позднем получении её вердикта.
Поздние посылки сохраняются в общей истории, но не входят в положение и список
посылок контеста. Изменение срока сразу пересчитывает зачёт по сохранённой
истории: сокращение исключает поздние посылки, продление возвращает их.
После истечения срока запущенный контест отображается завершённым;
продление такого контеста снова открывает зачёт. Кнопка «Завершить» также
устанавливает время отсечения, не сдвигая уже прошедший срок вперёд.
Старые контесты без `ends_at` сохраняют прежнее поведение до установки срока.

На странице контеста вместо даты окончания показан таймер. До запланированного
начала он показывает полную длительность, после начала — обратный отсчёт,
после окончания — ноль. Если у черновика не задано начало, длительность
не определена и показан прочерк. Таймер расположен справа от названия контеста.

## Сводная таблица группы

На странице группы показаны все её участники и задачи видимых контестов,
сгруппированные по контестам. Повторяющиеся задачи имеют отдельные столбцы
и результаты в каждом контесте. Скрытые контесты исключаются даже для владельца.
Результаты используют тот же интервал зачёта, что и положение отдельного
контеста. Таблица обновляется каждые 30 секунд, по кнопке и после изменения
состава участников; имена участников и заголовки закреплены при прокрутке.
API `GET /api/v1/groups/{id}/scoreboard` доступен владельцу группы и её участникам.

## Просмотр интерфейса ученика

Добавьте `?view=student` к адресу страницы (или `&view=student`, если в адресе
уже есть параметры). Например, `/contests/41?view=student` или
`/problems/1?contest=41&view=student`. Преподавательские кнопки и настройки
администратора скрываются, появляются ученические вкладки; скрытые контесты
не показываются. Параметр сохраняется во внутренних переходах. Удалите его,
чтобы вернуться к обычному виду.

Это предпросмотр интерфейса: роль аккаунта и серверные права не меняются,
свои посылки и привязки к проверяющим системам остаются от текущего аккаунта.

## Тесты

Проверки фронтенда, включая восстановление сессии и обработку ошибок входа:

```bash
cd frontend
npm test
npm run build
```

```bash
cd backend
pip install -r requirements-dev.txt
PYTHONPATH=. pytest -q
```

По умолчанию тесты используют изолированную SQLite в памяти. Для проверки
на PostgreSQL задайте `TEST_DATABASE_URL`, указывающий на отдельную тестовую
базу: тесты создают и удаляют таблицы в ней.
