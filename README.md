# AlgosyHub

Учебная платформа для групп по спортивному программированию.

## Быстрый старт

```bash
cp .env.example .env
# заполнить .env
docker compose up --build
```

Backend: http://localhost:8000  
Frontend: http://localhost:5173  
API docs: http://localhost:8000/docs

## Production: algosy.thamgr.space

Платформа развёрнута на `5.178.109.118` в `/opt/algosyhub`.
Используется отдельный `compose.production.yml`: снаружи доступны только
HTTP/HTTPS, Caddy автоматически выпускает и продлевает TLS-сертификат.
Контейнеры запускаются после перезагрузки сервера; PostgreSQL и сертификаты
хранятся в постоянных Docker volumes. Логи ограничены по размеру.

В серверном `.env` нужны настройки интеграций из `.env.example`, уникальный
`SECRET_KEY` и случайный `DB_PASSWORD` (hex, минимум 32 байта).
Файл должен иметь права `600`; секреты не добавляются в Git.
Не меняйте `DB_PASSWORD` без соответствующей смены пароля в PostgreSQL.

Команды на сервере:

```bash
cd /opt/algosyhub
docker compose -f compose.production.yml up -d --build --wait
docker compose -f compose.production.yml ps
docker compose -f compose.production.yml logs --tail=100 backend caddy
curl --fail https://algosy.thamgr.space/healthz
```

Перед обновлением исходников и миграциями сохраните резервную копию базы:

```bash
cd /opt/algosyhub
install -d -m 700 backups
umask 077
docker compose -f compose.production.yml exec -T db \
  pg_dump -U postgres -d algosyhub -Fc > "backups/algosyhub-$(date +%Y%m%d-%H%M%S).dump"
```

Обновляйте исходники, сохраняя серверный `.env`, затем повторяйте `up`.
Миграции применяются автоматически перед запуском API.
Не используйте `down -v`: эта команда удаляет постоянные данные.

## Глобальные настройки

Администратор открывает «Настройки платформы» в шапке (`/platform-settings`).
Переключатели сохраняются автоматически в базе:

- **Регистрация пользователей**: скрывает ссылку и форму регистрации,
  а также запрещает создание аккаунтов через API. Вход продолжает работать.
- **AI-подсказки**: скрывает блок подсказок и настройки подсказок в контестах,
  запрещает чтение кэша, генерацию и перегенерацию. Индивидуальные настройки
  контестов сохраняются и снова действуют после включения глобального флага.
- **Темы задач**: показывает темы и теги на страницах задач и в списках задач,
  включая редактирование контеста. По умолчанию выключен.
- **Сложность задач**: показывает сложность на странице задачи и в списке задач
  контеста. По умолчанию выключен.
- **Запрет редактирования ФИ и ID учениками**: делает ФИ и ники/ID в профиле
  ученика доступными только для чтения. API запрещает изменение и очистку ФИ,
  добавление, замену и удаление привязок проверяющих систем. Ограничение
  проверяется по текущей роли пользователя при каждом запросе; выбор эмодзи
  остаётся доступен. Миграция `0012` добавляет переключатель, по умолчанию
  выключенный. Включается администратором в глобальных настройках.

Регистрация и AI-подсказки по умолчанию включены. Миграция `0011` добавляет
оба переключателя отображения выключенными, сохраняя остальные настройки.
Темы и сложность остаются в данных задач и доступны для подбора контестов.

Открытые страницы обновляют настройки при переходах, возврате в окно и каждые
30 секунд. API проверяет актуальные значения при каждом запросе.

Право администратора независимо от роли учителя и не выдаётся при регистрации.
Его можно назначить только существующему аккаунту командой на сервере:

```bash
cd /opt/algosyhub
docker compose -f compose.production.yml exec -T backend python -m app.manage admin USERNAME
# Отозвать: добавить --revoke. Для обновления интерфейса перезагрузите страницу.
```

Миграция `0006` добавляет настройки и право администратора без изменения
существующих аккаунтов. `GET /api/v1/platform-settings` публично возвращает
только два флага, `PATCH` доступен только администратору.

## Личный кабинет

На своей странице `/u/USERNAME` настройки расположены справа от профиля и
статистики; на узком экране — ниже. В одном блоке находятся поле «Фамилия Имя»
и ники/ID проверяющих систем. Выбор эмодзи открывается по нажатию на большую
аватарку слева в своём профиле; выбранный эмодзи сохраняется сразу. ФИ необязательны:
профиль, шапка, участники группы и таблицы результатов показывают ФИ, если они
заданы, иначе — ник. Без эмодзи аватарка показывает инициалы. Ник после
регистрации не меняется и остаётся в адресе профиля.
Старый адрес `/settings` перенаправляет к настройкам в профиле.

`PATCH /api/v1/me` принимает `full_name` (до 201 символа) и `avatar_emoji`.
Переданные значения сохраняются независимо, пустая строка очищает поле;
пробелы по краям удаляются. Список доступных эмодзи возвращает
`GET /api/v1/me/avatar-options`, сервер проверяет выбор по этому списку.
Изменение ника и прав через этот API запрещено. Миграция `0009` объединяет
ранее сохранённые фамилию и имя, `0010` добавляет пустую аватарку существующим
аккаунтам, сохраняя логины и привязки.

Статистика профиля учитывает посылки контестов только в интервале
`[starts_at, ends_at)`, как положение контеста. Это правило действует для
числа решённых задач, общего числа посылок и доли успешных. Изменение дат
сразу пересчитывает статистику при следующем запросе профиля; история
посылок сохраняется. Посылки без привязки к контесту учитываются как прежде.

## Условия Codeforces

Если основной сайт не отдаёт условие, сервер пробует `mirror.codeforces.com`
и `m1.codeforces.com`. Принимается только непустой блок `problem-statement`:
страницы проверки браузера не отображаются как условие и не попадают в подсказки.
Успешные ответы хранятся в памяти процесса один час (до 128 задач).
Если все источники недоступны, API возвращает 502 с пояснением, а страница
предлагает повторить запрос или открыть условие на Codeforces.

## Timus

В создании и настройках контеста выберите источник **Timus** и укажите номер
задачи, например `1000`, или ссылку на её условие. Поддерживается основной архив
Timus (`space=1`): импорт названия, меток и сложности, просмотр условия,
AI-подсказки и переход к форме отправки решения.

В настройках профиля привяжите числовой ID автора из публичной ссылки
`https://acm.timus.ru/author.aspx?id=12345`. Это числовая часть `JUDGE_ID`
без букв в конце: например, из `12345AB` нужно ввести `12345`.
Полный `JUDGE_ID`, пароль и ключ API для опроса Timus не нужны.
Посылки читаются с публичной страницы статуса; время Timus переводится из
часового пояса Екатеринбурга в UTC. Как и у остальных адаптеров, за один опрос
синхронизируются последние 50 посылок пользователя.

Для существующей базы требуется миграция `0005` (`alembic upgrade head`).
При запуске через Docker Compose миграции применяются автоматически.

## Время и видимость контеста

Контест идёт только в интервале `[starts_at, ends_at)`. До начала и после
окончания он неактивен. Ручного статуса и кнопок запуска/завершения нет.
API возвращает вычисляемый `is_active`; поля `status` и маршруты `/start`,
`/finish` удалены. Обе даты необязательны: `null` означает отсутствие границы.
Без обеих дат контест идёт постоянно. API принимает ISO 8601 с часовым поясом,
формы используют часовой пояс браузера. Владелец может менять обе границы и
состав задач независимо от текущего времени.

До начала участникам доступна карточка контеста, но не задачи, условия,
подсказки, положение и посылки. Такие задачи также не раскрываются через
общий список задач, прямой API и сводную таблицу группы. Владелец может
готовить и просматривать задачи заранее. Если задача уже доступна через
другой начавшийся контест, её отдельная страница остаётся доступной, но
контекст будущего контеста закрыт. Условия загружаются с авторизацией и
показываются в изолированном iframe. После окончания задачи остаются доступны.

Флаг «Виден участникам» (`is_visible`) действует независимо от времени.
Если он выключен, только владелец видит контест. Если включён, действуют
ограничения выбранных групп. Настройки видимости не меняют сохранённые результаты.

Зачёт определяется временем отправки: начало включительно, окончание строго
исключительно. Посылка, отправленная вовремя, учитывается и при получении
вердикта после окончания. Синхронизация начавшихся контестов продолжается
после окончания; поздние посылки сохраняются в истории, но не входят в зачёт.
Изменение границ пересчитывает зачёт по сохранённой истории без удаления
посылок. При повторной синхронизации сохраняются их исходные время и контест.

Таймер справа от названия показывает полную длительность до начала,
обратный отсчёт во время контеста и ноль после окончания. Без определённой
длительности или срока окончания показан прочерк.

Миграция `0013` удаляет только ручной статус. Даты, видимость, связи задач
и групп, ID посылок, их время и вердикты остаются неизменными.

## Настройки группы

Шестерёнка справа от названия группы открывает `/groups/{id}/settings`.
На этой странице учитель-владелец меняет название и управляет участниками.
На основной странице остаётся сводная таблица. Другие пользователи, включая
администратора без владения группой, не могут открыть настройки или изменить
группу. В режиме `view=student` шестерёнка скрыта.

`GET /api/v1/groups/{id}/settings` и `PATCH /api/v1/groups/{id}` проверяют роль
учителя и владение группой. Обновление принимает только `name`: от 1 до 200
символов после удаления пробелов по краям.

## Сводная таблица группы

В настройках группы владелец может добавить пользователя по логину в отдельный
список «Наблюдатели». Наблюдатель видит группу, её опубликованные контесты,
результаты и материалы, но не может изменять их, управлять участниками или
назначать группе свои контесты. Задачи открываются после начала контеста;
скрытые контесты остаются недоступны. Наблюдатели не входят в состав учеников
и таблицы результатов. Роль аккаунта (учитель/ученик) не меняется.
Удаление из наблюдателей сразу отзывает доступ. Миграция `0015` добавляет
таблицу `group_observers`, сохраняя существующий состав групп.

`POST /api/v1/groups/{id}/observers` принимает `username`,
`DELETE /api/v1/groups/{id}/observers/{user_id}` удаляет наблюдателя.
Оба действия доступны только учителю — владельцу группы. Список наблюдателей
возвращается в `GET /api/v1/groups/{id}/settings`.

На странице группы показаны все её участники и задачи видимых контестов,
сгруппированные по контестам. Без видимых задач таблица содержит список
участников; столбец «Решено» и столбцы задач появляются, когда есть задачи.
Повторяющиеся задачи имеют отдельные столбцы
и результаты в каждом контесте. Скрытые контесты исключаются даже для владельца.
Результаты используют тот же интервал зачёта, что и положение отдельного
контеста. Таблица обновляется каждые 30 секунд и после изменения
состава участников; имена участников и заголовки закреплены при прокрутке.
API `GET /api/v1/groups/{id}/scoreboard` доступен владельцу группы и её участникам.

## Просмотр интерфейса ученика

Добавьте `?view=student` к адресу страницы (или `&view=student`, если в адресе
уже есть параметры). Например, `/contests/41?view=student` или
`/problems/1?contest=41&view=student`. Преподавательские кнопки и настройки
администратора скрываются, появляются ученические вкладки; скрытые контесты
не показываются. Параметр сохраняется во внутренних переходах. Удалите его,
чтобы вернуться к обычному виду.

Это предпросмотр интерфейса: роль аккаунта и серверные права не меняются,
свои посылки и привязки к проверяющим системам остаются от текущего аккаунта.

## Тесты

Проверки фронтенда, включая восстановление сессии и обработку ошибок входа:

```bash
cd frontend
npm test
npm run build
```

```bash
cd backend
pip install -r requirements-dev.txt
PYTHONPATH=. pytest -q
```

По умолчанию тесты используют изолированную SQLite в памяти. Для проверки
на PostgreSQL задайте `TEST_DATABASE_URL`, указывающий на отдельную тестовую
базу: тесты создают и удаляют таблицы в ней.

## Материалы курса

На странице группы над сводной таблицей находится горизонтальная лента материалов.
Карточка показывает заголовок по центру по высоте и дату без года; полный год
сохраняется в базе. Новые даты идут первыми, при одинаковой дате — последние
добавленные материалы. По нажатию открываются описание и именованные ссылки
в отдельном окне; ссылки открываются в новой вкладке.

Преподаватель-владелец добавляет материал кнопкой «+». В форме обязательны
заголовок, дата и хотя бы одна ссылка; описание необязательно. Можно добавить
до 20 ссылок HTTP/HTTPS. В режиме ученика кнопка скрыта. API разрешает чтение
только владельцу и участникам группы, создание — только учителю-владельцу.

`GET /api/v1/groups/{id}/materials` возвращает материалы группы,
`POST /api/v1/groups/{id}/materials` принимает `title`, `date` (YYYY-MM-DD),
`description` и `links` — массив `{label, url}`. Миграция `0014` создаёт отдельную
таблицу материалов, не меняя существующие группы, задачи и результаты.

Карандаш в попапе материала доступен преподавателю-владельцу и открывает
редактирование заголовка, даты, описания и списка ссылок. Отмена не меняет
сохранённые данные. `PUT /api/v1/groups/{id}/materials/{material_id}` принимает
тот же полный набор полей, что создание; идентификатор материала сохраняется.
Проверяется принадлежность материала группе и право преподавателя-владельца.
